## 动画环境修补依据

此前只通过 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 传递动画／缩放参数，通过 `WEBVIEW2_USER_DATA_FOLDER` 指定隔离数据目录。本地通过并不能证明云端应用了这些参数。

微软文档明确指出：管理员权限的 WebView2 宿主会忽略 `WEBVIEW2_*` 环境覆盖，但会尊重应用经原生 API 设置的选项。[官方说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security#for-an-elevated-host-app-use-appropriate-override-flags)

本轮日志确认参数的预期效果未生效；管理员权限是与官方行为一致的解释，旧日志没有记录实际令牌权限，不能将其冒充已直接测量的结果。CI 新增权限状态摘要，供下一轮核对。

修补只进入 `e2e` 特性构建：启动前写入 Tauri 窗口的 `additional_browser_args` 和 `data_directory`，动态设置窗口及重建桌宠共用相同配置。移除测试脚本对 `WEBVIEW2_*` 环境覆盖的依赖。生产构建不包含该模块，不改变用户系统动画设置，也不修改前端状态判断或伪造 `matchMedia`。

- 两处 artifact 上传显式开启 `include-hidden-files`；继续按文件白名单上传，不上传 runtime、token、用户配置或 WebView 数据。桌面报告为空改为明确报错。该开关用途见 [upload-artifact 官方说明](https://github.com/actions/upload-artifact/tree/v4#uploading-hidden-files)。

## 第四轮：唤醒动画检查受到远程读取延迟影响

用户更新于 2026-10-30 17:05 的日志，桌面套件启动于 `2026-10-30T05:28:44Z`。这次实际媒体偏好已为 `systemReducedMotion=false`，12 项功能通过，唯一失败为 `Waking from low FPS must start near the entry's beginning`。失败现场为 DOM、手动预览、thinking-enter 第 25 帧；核心 working、待处理 0，状态传递正常。重启检查已正确跳过，没有再产生 Pixi/DOM 连带断言。

旧检查先远程等待入场动画可见，再通过另一次 WebDriver 调用读取当前帧，要求小于 20。入场动作 48 FPS，第 20 帧约在 417ms；读取端变慢会把已经正常推进的帧误当成起始帧。云端旧现场没有保存第一帧，无法由第 25 帧反推出真实起始帧。

本地在旧检查读取前加 600ms 延迟，不修改桌宠逻辑，复现完全相同的失败：`.test-artifacts/ui-wake-old-1793351492109`。临时改动已还原。

修补内容：

- 测试触发唤醒前，在 WebView 内注册同步绘制监听，保存首次入场帧、首次完成混合的帧及至少 250ms 的采样。记录最多 80 条，并设置截止与退出清理。
- `e2e` 前端记录每次绘制的单调时间和实际片段 FPS，区分绘制时间、监听收到时间和远程读取时间；正常构建会去除字段和采样事件。
- 严格要求第一帧为 0，并按实际绘制间隔验证后续帧没有提前跳进度；一帧容差用于时钟采样与取整。人为再延迟 450ms 读取，断言仍使用已保存的开始过程。
- 保存 `thinking-pixi-wake.json`／`thinking-dom-wake.json`，CI 按白名单上传，未来可直接核对第一帧、绘制时间和晚读到的帧。
- 8 项工具测试通过，包括接受晚到的观察／读取、拒绝第 25 帧起播，以及拒绝把休眠间隔计入新动作。

采样验证中，MutationObserver 会合并一个事件内的连续 DOM 绘制，首次看到第 3 帧；该候选实现已弃用，改成每次绘制完成渲染属性设置后同步发送事件，避免遗漏第 0 帧。该候选运行 `.test-artifacts/ui-2026-10-30T09-13-53-272Z` 不计为通过。

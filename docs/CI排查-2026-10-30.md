## 动画环境修补依据

此前只通过 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 传递动画／缩放参数，通过 `WEBVIEW2_USER_DATA_FOLDER` 指定隔离数据目录。本地通过并不能证明云端应用了这些参数。

微软文档明确指出：管理员权限的 WebView2 宿主会忽略 `WEBVIEW2_*` 环境覆盖，但会尊重应用经原生 API 设置的选项。[官方说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security#for-an-elevated-host-app-use-appropriate-override-flags)

本轮日志确认参数的预期效果未生效；管理员权限是与官方行为一致的解释，旧日志没有记录实际令牌权限，不能将其冒充已直接测量的结果。CI 新增权限状态摘要，供下一轮核对。

修补只进入 `e2e` 特性构建：启动前写入 Tauri 窗口的 `additional_browser_args` 和 `data_directory`，动态设置窗口及重建桌宠共用相同配置。移除测试脚本对 `WEBVIEW2_*` 环境覆盖的依赖。生产构建不包含该模块，不改变用户系统动画设置，也不修改前端状态判断或伪造 `matchMedia`。

## 其他修补

- 只有主界面功能均成功、最后的重启前置场景完成时才运行重启检查；纯截图差异仍允许完成重启验证，保留候选基准审阅流程。
- 前置流程失败时，将重启项记为 `skipped` 和 `passed:false`，保留最初错误；没有执行截图时记录 `not-run`。
- 每轮初始化验收文件，避免重用目录读到上次的通过标记。
- 两处 artifact 上传显式开启 `include-hidden-files`；继续按文件白名单上传，不上传 runtime、token、用户配置或 WebView 数据。桌面报告为空改为明确报错。该开关用途见 [upload-artifact 官方说明](https://github.com/actions/upload-artifact/tree/v4#uploading-hidden-files)。

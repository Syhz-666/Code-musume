# 权限误报修复与安装验证链路 — 2026-11-12

## 问题

- **迟到权限的幻影等待**：两家的 PermissionRequest 都不带 tool ID。原有"迟到权限不能重开已终结工具"的保护只在带 ID 时生效，真实事件中从未执行。工具完成后才到达的权限请求会显示「等你处理」，要等该轮结束才消失。临时测试已在本机复现。
- **Codex 桌面同步失效时不再提示**：开启桌面审批同步后，Codex 的 hook 权限请求会被整条丢弃。桌面版本不兼容或管道断开时，Codex 端不再显示等待，也没有回退。
- **回归样本形状不真实**：原测试给 PermissionRequest 带上了 tool ID，因此一直通过。

## 修改

- 权限判定（`crates/core/src/engine.rs`）：同轮次、同工具名、同输入的工具已全部完成时，迟到请求不再进入等待，诊断记为 `completed-tool`。工具名或输入缺一时不作此判断。三者都缺的工具审批丢弃，诊断记为 `uncorrelated-permission`。Claude 的权限通知照常等待。只带工具名的请求，在同轮唯一同名工具完成时解除。
- Codex 交接：hook 请求始终记录。桌面有快照时，等待数以桌面为准，并清除早于该快照的 hook 请求。桌面失联后由 hook 接管，可信度标为较旧。未知审批方法计为需要处理，不保留方法名。拒收的帧按版本、结构、修订分类计数；会话状态分为 observed / degraded / never。设置页诊断显示同步状态。
- 新增 11 个固定场景，包含三种交接时序；回放框架支持 `codexApprovalSync`、`approvals`、`desktop-lost`。
- `package-windows.ps1` 改为按「版本-提交」输出到独立目录，只拷贝并校验本次产物，并打印 `SETUP=`。
- `test-installer.ps1` 改为必须显式传入安装包，新增 Codex 内联 TOML 用例。它按 UTF-8 读取 CLI 输出，失败时也写 `result.json`，并卸载残留的安装。
- CI 新增 `installer` job。新增手动 `release` workflow：只接受已有 tag，tag 必须与版本一致；发布前先运行安装验证并复核 SHA-256。
- 忽略本机 `.codex/hooks.json` 与安装器备份，删除遗留 `hello.py`。

## 验证边界

- 本次证据覆盖两点：hook 路径的迟到误报已修复；桌面同步失效时不再完全不提示。现有样本**不能证明**生产 IPC 路径上没有其他误报。
- hook 回退期间，Codex 的请求可能已经被自动审批，所以显示为较旧，不作确定等待。
- 桌面的 `conversationId` 与 hook 的 `session_id` 是否一致，目前只有测试证据。如果不一致，诊断会显示 `unknown-session`，行为退化为只使用 hook。
- 待人工验收：真实 Codex 桌面首次连接、断开、重连时设置页诊断的变化；干净 Windows 账户与用户级接线；CI 上的 `installer` job 需推送后确认。
- 已知遗留：安装器写回 Codex TOML 时，会把 `[[hooks.X]]` 表格改写为单行内联表。内容等价，但会改动用户文件的格式。

# 状态规范 — 2026-10-14

> 现行，取代旧单一 state 赋值与基于来源时间整体丢弃的规则。行为在 Rust core 实现；前端不得重新判断。

## 三类内部模型

活动：空闲、思考、工具执行、压缩和已知背景工作。待处理事项：权限/输入请求，直到解除证据。提示：轮次结束、普通通知、错误，独立期限，不覆盖底层活动。

显示仍为 8 态，优先级：waiting-permission(100) > error(90) > done(80) > notification(70) > working(60) > thinking(50) > idle(20) > sleeping(10)。提示结束重新投影底层活动，不直接赋 idle。done 只表示这轮回复结束。

## 身份与关联

会话键为来源+session ID；轮次由 adapter 统一 turnId。缺失 session 不新建伪会话；执行主体缺失仅更新未细分活动。事件按接收序串行应用，单调时钟驱动期限；来源 ts 不能证明全局因果顺序。

工具与轮次保留有限终结记录，迟到 start 不能重开已完成对象；每会话最多 64 主体，每主体最多 256 工具、64 待处理与64终结轮次。来源重复 id 不重放。

权限优先按同主体/轮次/tool ID 关联；缺 ID 时用工具名与规范化输入哈希辅助判断。歧义保留等待。对应成功、失败、拒绝清除对应请求；Stop / Interrupt 清理相应主体轮次，SessionEnd 清理会话。无关工具、子 agent 和另一家不能解除等待。

Prompt 开始新轮次并清理前轮次短暂完成提示；ActorStart/End 只改变相应主体；压缩显示思考，结束后恢复活动。明确工具失败、拒绝或轮次失败生成短暂 error；文本中出现错误字样不构成失败证据。未知事件不驱动状态。

## 时间与容量

|行为|默认|
|---|---|
|done 提示|3s|
|notification 提示|4s|
|error 提示|30s|
|活动静默减弱|60s|
|活动转为不确定|5min|
|等待减弱、不自动消失|10min|
|全局空闲睡眠|10min|
|触摸反馈冷却|5s|
|会话上限|8|

重复提示不延长期限，动画驻留不阻挡新语义。执行主体的静默期限独立计算，父主体的新事件不刷新失联子主体。容量优先回收已结束、空闲与失联；仍满拒绝新会话并诊断，不淘汰等待会话。事件丢失降低已有会话可信度，新轮次可恢复该会话可信度，累计丢失数量保留供诊断；用户也可清理旧状态等待新证据。

## 聚合与形态

先取最高显示优先级，同级保持当前来源直到结束/失联，否则择最新有依据的会话。等待与错误立刻切主导来源和形态；一家完成后提示 3s，再恢复仍忙的另一家。

形态：锁定 > 用户覆盖 > 角色包来源映射 > 默认。无规则 DSL。idle 微动作与触摸由表现层调度，不改工作状态；等待时陪伴动作让位，减少动画时使用静帧。

## 验收证据

Rust 情景测试覆盖并发、完成回落、权限隔离、迟到、重复、时间、容量与隐私。TS 只验证快照修订防倒退。native/CLI 真实 HTTP 链路与窗口测试独立；真人双会话、信任、资源及一天日用另记，不用合成事件替代。

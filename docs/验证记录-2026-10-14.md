## 真实 Claude 样本

安装的 Claude Code 2.1.295，配置的 DeepSeek API。隔离项目中只读取无敏感内容的 fixture.md。实际收到 SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop；prompt_id 在提交/工具/结束事件中一致，tool_use_id 在开始与结束对应。发布版最后回到 idle，主导来源与形态为 Claude，missedEvents=0。

证据：fixtures/hooks/captured-claude-2.1.295.json。这是 real-redacted，保留身份字段与事件来源，去掉 prompt、代码、cwd、transcript、工具输入/响应及消息；部分载荷不能当完整重放样本。

采集使用 tools/capture-live-hooks.ps1 的限定时长回环转发器，原信封只在内存中转发给核心，存储白名单字段。实际 Claude 正常流程已验证；权限、失败、压缩、子主体仍以情景测试和后续人工验证补齐。

## 渲染与资源

短时调试版可见工作动画平均约 59.3 FPS、进程树专用工作集峰值约 148.4MiB；修正后的空闲采样约 0.68% CPU、124.5MiB。包含 WebView 子进程，CPU 按整机核心容量归一化。最初 PowerShell 采样因整数重载截断得到 0，已弃用，改为原生计数器和 double 运算。

发布版完整 600 秒采样完成：空闲平均 CPU 0.6945%，应用与 WebView 子进程专用工作集峰值 114.57MiB。窗口可见、内置角色、Pixi、系统 125% DPI；末尾按规则进入 sleeping，CPU 均值只统计 idle 样本（220 条）。原始数据在 .test-artifacts/live-claude/idle-10min.json，便于入库的汇总在 docs/exps/资源采样-2026-10-14.json。FPS 由实际前端上报；无近期可见前端时为 null，不能用 headless 假设帧率。实际外部角色负载仍需验证。

## 已解决的阻断

- 自动审批服务曾因额度不足未执行一批检查，后续恢复并完成本地检查。
- Claude Code 网络调用先遭 DNS 失败；源码审查外发被自动审批拒绝后，用户明确授权 crates/core 与 hooks/cli 发往配置的 DeepSeek API，只读复查随后完成。采纳迟到权限、恢复可信度、回滚与清理作用域问题；没有采用无关联证据就清除等待的建议。
- Tauri 内置下载器取得 NSIS 超时；系统下载器取得同一官方版本和插件，按 Tauri CLI 2.12.2 官方源码的校验值验证，在项目工具缓存完成打包。
- Windows PowerShell 的 UTF-8 读取与 Get-FileHash 加载问题已修复，校验使用 .NET SHA256。

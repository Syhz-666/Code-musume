## 3. 结果（已实测）

### 3.1 窗口原生属性（win-probe 原始输出，DPI-aware）

```
HWND 0x19086C  Visible=True  Class="Tauri Window"
Rect: 32,32 -> 432,482 (400x450)      ← 物理像素（DPI-aware）
ExStyle = 0x08240118 = TOPMOST | NOACTIVATE | NOREDIRECTIONBITMAP (+窗口边框类常规位)
foreground: 终端窗口（未被本窗口抢占）
```

- 非 DPI-aware 读数为 `26,26 -> 346,386 (320x360)`——**同一窗口两套读数，比值恰为 1.25**
  → 本机显示缩放 = **125%**；说明「坐标系陷阱」在本机真实存在（沿用项目教训：坐标以实测为准）。

### 3.2 视觉验证（截图 `tmp-shots/pet-window.png`，物理区 32,32 400×450）

- 占位圆（浅蓝填充 + 深蓝描边，抗锯齿）悬浮于桌面与终端之上；
- 窗口区域**无白底 / 无黑底 / 无边框 / 无阴影**，背景（桌面图标、终端文字）正常透出；
- 圆位于窗口中心（200,225 物理）→ Pixi 画布布局正确。

# 实验记录 — `Config.json` 热重载假设被否证

> 实验日期：2026-10-09 16:12 – 16:31
> 实验者：Claude Code（接手智能体）
> 结论：**HANDOFF 第 2 节「已实测确证」的核心结论不成立。`Config.json` 是程序的纯输出，不是外部可控的输入。**
> 证据等级：本轮结论为**实测确证**；个别推断已明确标注。

---

## 0. 一句话结论

**天选姬每 422 秒把 Config.json 用自己的内存状态整个重写一遍；外部写入的 `OneTimeAlarm` 在下一次重写时被直接覆盖，程序从未读取过它。**

→ 「外部写配置文件驱动官方桌宠」这条路**不成立**。

---

## 1. 实验一：外部写入的闹钟在目标时刻前被覆盖

### 设计

| 步骤 | 时刻 |
|---|---|
| 备份 Config.json | 16:13:00 |
| 写入 `OneTimeAlarm = 2026-10-09T16:14:50`（写入时刻 +60s，字节级、长度不变 2413 bytes） | 16:13:50 |
| 高频观测（1s 轮询窗口+配置字段，5s 截图右半屏） | 16:13:40 – 16:16:25 |

### 结果

| 观测项 | 结果 |
|---|---|
| 165 秒内 `OneTimeAlarm` 是否被消费 | ❌ 否。到观测结束（超出目标 95 秒）仍是 `2026-10-09T16:14:50` |
| 目标时刻视觉反应 | ❌ 无。帧差异 0.0–0.3（16×16 灰度签名，256 级） |
| 是否有新窗口出现 | ❌ 无。全程只有 `ASUSMascot@1749,856,1903,1010` |
| 16:18:49（观测结束后 2 分钟）程序重写配置 | ✅ `OneTimeAlarm` → `0001-01-01T00:00:00`，心跳 → `16:18:48` |

**注意 16:18:49 这一次**：程序主动写了配置文件，但此时距我写入已经 299 秒——它**没有在中间任何一个时刻**把这个值当输入使用。

---

## 2. 发现 422 秒周期

心跳字段 `lastRecordUseTime` 的实测值序列：

```
16:04:44  →  16:11:46  →  16:18:48  →  16:25:50
            422 s        422 s        422 s
```

配合 mtime：`16:18:49`、`16:25:51`。**周期 = 422 秒，精确稳定。**

程序每次周期写入会把 Config.json 全部字段用内存状态覆盖一遍。

## 3. 实验二：决定性验证（值活过了周期，但被抹掉）

实验一无法区分两种可能：(a) 程序不读文件；(b) 程序在周期时读文件，只是把过期闹钟丢弃。
实验二把闹钟目标设到**下一次周期重写之后**，从而把两者分开。

### 设计

| 步骤 | 时刻 |
|---|---|
| 写入 `OneTimeAlarm = 2026-10-09T16:29:00` | ≈16:20:10 |
| 预测的下一次周期重写（= 16:18:49 + 422s） | ≈16:25:50 |
| 目标时刻（周期之后 3 分 10 秒） | 16:29:00 |
| 观测 | 16:20:21 – 16:31:32（640s，112 帧） |

### 结果

| 观测项 | 结果 |
|---|---|
| 16:25:51 周期重写是否保留未来闹钟 | ❌ **抹成 `0001-01-01`**。此时目标时刻**还有 3 分 9 秒才到** |
| 周期预报准确度 | ✅ 预测 16:25:50，实测 16:25:51 |
| 16:29:00 目标时刻视觉反应 | ❌ 无。帧差异 0.0 / 0.1 / 0.1 |
| 是否有新窗口出现 | ❌ 无 |
| 观测灵敏度正向对照 | ✅ 同期终端文字滚动被准确检出（帧差异 195.1 / 77.2 / 75.4） |

### 为什么这是决定性的

如果程序读取了这个值，一个**指向未来**的闹钟没有任何理由被清空——正常实现要么保留它，要么按点触发。
它既没保留（16:25:51 被抹），也没触发（16:29:00 无反应）。
**唯一的自洽解释：程序根本没有读取该字段。**

## 4. 前人结论为何看起来成立：一个重言式

HANDOFF 第 2.1 节的两组数据：

| | 写入 | 目标 | 「清零」 |
|---|---|---|---|
| 实验一 | 23:51:14 | 23:52:44 | 23:53:35 |
| 实验二 | 23:55:46 | 23:59:46 | 00:00:37 |

拆解：

- **两次「清零」相差 422 秒** → 与今日实测的周期**完全一致**，它们就是两次周期重写，不是「消费」。
- **两次「目标时刻」也相差 422 秒**（写入间隔 272s + 提前量差 150s = 422s）。
- 既然「目标」等距、「清零」也等距，那么「清零 − 目标」**必然两次相等**。

所以「两次都精确落在目标 +51 秒」**不是两个独立证据，是同一个数据点被数了两遍**。
后人据此推断「清零时刻被目标时刻驱动」——方向对，但那个「驱动」是实验设计本身带来的，不是程序行为。

### 遗留问题也因此被解释

前人两次实验都**没观测到任何视觉反应**，并用「全屏游戏遮挡」解释（且自己标注为推断）。
真实原因更简单：两次实验的「写入→目标」提前量分别是 90s 和 240s，**都短于 422s 周期**——
程序真正轮到处理这个字段时，目标时刻早已过去，值被当过期数据处理掉了。**从来没有反应可看。**

## 5. 顺带确证的文档错误

| HANDOFF 原文 | 实测 |
|---|---|
| 屏幕 1536×864 **物理**像素 | ❌ 物理 **1920×1080**；1536×864 是逻辑坐标（`mDpiScale = 1.25`） |
| `windowLeft`/`windowTop` 是物理像素，且「实测对比过」 | ❌ **逻辑坐标**。实测窗口物理矩形 `(1749,856)-(1903,1010)`；1399.2 × 1.25 = **1749.0**，684.4 × 1.25 = 855.5 ✅ |
| 窗口尺寸 | 154×154 物理像素，ExStyle `0x80088` |
| `isFullScreenActived` | 长期为 `true`，即使在无任何全屏程序的普通桌面下（很可能**陈旧值或实为设置开关**，非实时状态） |

> 📌 **这个坐标错误正是前人「截图抓错区域、只拍到终端」那个坑的真正成因**——不是「逻辑/物理」的判断失误，而是文档把结论记反了。

## 6. 残余不确定性（诚实标注）

1. **配置是否在程序启动时被读取一次**——未验证。
   本次实验只否证了「运行时热重载」。若配置在启动时被读取，那么「写配置 + 重启桌宠」理论上可能生效，但对 hook 接线毫无实用价值（不能在每个 hook 事件上重启桌宠）。
2. **`isFullScreenActived: true` 是否为实时状态**——未验证。
   若它是实时状态且用于抑制，理论上可能掩盖了 16:29:00 的反应。但即便反应被抑制，**文件值在 16:25:51 被抹掉这件事本身**也无法用抑制解释（抑制不该清空一个未来的闹钟）。因此该不确定性**不影响主结论**。
3. 程序周期性写入时，除 `OneTimeAlarm` 外是否还覆盖其它字段——未逐一验证，但已确认是整体写回。

## 7. 复现方法

### 工具（位于 `D:\AAA-MyProfile\Search\exp1\`）

| 文件 | 作用 |
|---|---|
| `recon.ps1` | DPI 感知的窗口枚举 + 屏幕尺寸 + 前台全屏判定（只读） |
| `setalarm.py` | 字节级写 `OneTimeAlarm`，断言长度不变、匹配唯一 |
| `observe.ps1` | 周期采样：配置字段 + 窗口枚举 + 前台全屏标志 + 右半屏截图 + 16×16 灰度签名 |
| `analyze.py` | 从签名计算逐帧差异，定位视觉变化时刻 |
| `shot.ps1` | 单次区域截图（DPI 感知） |

### 关键复现步骤

1. 记录 `lastRecordUseTime`，等两到三次，确认周期为 422 秒
2. `python -I setalarm.py "<Config.json>" <秒数>` 写入未来时刻
3. `observe.ps1` 高频观测，直到跨越「下一次周期重写」或「目标时刻」
4. 判定：
   - 值在周期重写时被抹 → **程序不读该字段**（本次结果）
   - 值被保留且到点触发 → 热重载成立

### ⚠️ 方法学要点（踩过的坑）

- **PowerShell 必须 `SetProcessDPIAware()`**，否则拿到的是逻辑坐标，截图会抓错区域
- 观测区域要**包含她的窗口**，并且要有**正向对照**（例如让终端滚动，确认差异检测有效），否则「无变化」无法与「监测失灵」区分
- 窗口枚举按 Class 含 `TX Mascot` 匹配（`MainWindowHandle` 因 TOOLWINDOW 恒为 0）

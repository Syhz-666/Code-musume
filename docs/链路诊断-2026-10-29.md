# 链路诊断与失败证据

## 目的

失败时区分「CLI 没有送达」「HTTP 收到但核心拒绝」「核心已经改变状态但界面没提交画面」。HTTP 202 仅代表接收，不代表事件语义有效。
诊断记录不改变状态判断，不重试 hook，不延长 300ms／100ms 截止。

## 能看到的信息

| 环节 | 记录 |
| --- | --- |
| CLI | 编译版本、事件来源和已知事件名、输入字节数、UTF-8 与 BOM 标志、JSON 是否有效、错误类别与行列、各阶段相对耗时、发送结果、HTTP 状态 |
| HTTP | 鉴权／Origin 拒绝、限流、信封过大或无效、事件输入结构检查、队列不可用 |
| Rust 核心 | 事件短标识、处理结果、处理前后状态、来源、可信度、待处理和丢失数量、快照修订号、接收到处理完成的耗时 |
| 投影／显示 | 发布修订号、当前订阅数、前端画面回执；手动预览拒绝冒充真实画面的回执会另行记录 |
| 桌面测试 | 两个窗口的状态、系统与应用动画偏好、可见性、焦点、字体状态、WebView／Node 版本、DPR、窗口和内容尺寸、滚动条宽度、测试来源提交与本机修改标志 |
| 截图 | 差异比例、差异像素数、差异区域边界、实际环境与基准环境；阈值仍为 0.1／0.5% |

CLI 的 `traceId` 和宿主的 `eventId` 来自同一个事件 ID 的短摘要，可以关联。发布与回执使用快照修订号关联。
`atMs` 为宿主的单调时间，在 e2e 中可推进；阶段 `elapsedMs` 使用真实耗时，不能与模拟时间混算。

## 日常运行时导出

启动当前版本的桌宠后，在项目根目录执行：

```powershell
pnpm diagnostics --dev
# 发布模式省略 --dev；隔离实例可明确指定 runtime 文件。
pnpm diagnostics --runtime-file <runtime文件路径> --out .test-artifacts/diagnostics/report.json
```

默认输出 `.test-artifacts/diagnostics/latest.json`，控制台打印简短定位提示。工具在内存中读取 Bearer token 发起请求，报告不保存 token 或 runtime 文件内容。
读取接口是受现有鉴权、Origin 拒绝和限流保护的 `GET /v2/diagnostics`，另提供 Tauri `get_pipeline_diagnostics` 命令。
旧二进制不支持此接口，需要重新构建并启动；404 记录为接口不可用，不会冒充成功。

## 测试失败时

- `tools/smoke.ps1` 自动给每次 CLI 分配 `hook-NNN.json`，打印 `TRACE hook`；失败保存 `failure-projection.json` 与 `failure-diagnostics.json`，打印最后的输入错误与核心处理结果。
- 桌面测试打印 `[hook]`、`[visual]`、`[diagnostic]` 摘要，保存 `failure-N.json`。核心 HTTP 采集独立于 WebDriver；界面断开时仍尝试保留核心现场。截图保存单独处理，截图失败不会抹掉已有 JSON。
- hook 和套件收尾失败也采集报告，避免只对测试正文采集。
- Actions 上传上述报告、CLI 元数据、画面与差异图。没有上传 runtime 文件、用户级配置或会话原文。

例：无效输入的报告可同时出现 `input.errorKind=utf8-bom` 和同一事件的 `core.outcome=invalid-payload`；动画停在第 0 帧时会区分系统减少动画、应用减少动画和手动预览，而不是统一叫「没有显示」。

## 保留与隐私边界

- 宿主链路环最多 256 条，旧记录淘汰并统计 `evicted`；原核心记录仍最多 200 条。常驻日志保留在内存，应用退出后清空，导出才落盘。
- CLI 只有明确传入 `--diagnostic-file <新文件路径>` 时才保存，单次最多 4KiB，不覆盖已有文件。默认 hook 不落盘，stdout／stderr 继续为空。
- CLI 到截止时间可能来不及写完可选报告；缺少文件只能说明报告未完成或不可写，不能单独证明投递失败。事件状态和宿主记录仍需结合判断。
- 不保存提示词、代码、工具输入、原始会话 ID、认证头、令牌、JSON 错误原文。事件 ID 和会话 ID 仅短摘要，未知事件名统一记为 `other`。
- 测试报告中的项目工作目录、Node 安装位置出现在调用栈时，属于当前测试机器路径；它们不作为程序固定运行路径。

## 本轮验证

新增自动检查覆盖 BOM／非法 UTF-8／截断 JSON 的分类、内容不落盘、日志容量、缺失 runtime 与投递成功区分，以及 CLI 继续静默退出。
原生通路还故意送入含 BOM 的事件，确认可将 HTTP 输入和核心拒绝关联，且导出中没有测试提示词、原始会话 ID 和 token。

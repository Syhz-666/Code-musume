# Codex 同步协议 13 验收

Codex 桌面从本机已验证的 `26.1106.6628.0` 更新到 `26.1111.2228.0` 后，实测同步广播使用协议 13。旧版代码娘只接受协议 11，hook 仍能更新工作状态，但桌面同步不能提供新进度或审批状态。

当前接收协议 11 和 13。每个会话以有效快照为基线，同版本增量按修订号接续。遇到跨版本增量或缺失更新时，同步状态失效，重新订阅快照。未同步会话的审批按现有 hook 规则降级判断。

## 证据与回归

[`progress-v13.jsonl`](../fixtures/codex-sync/progress-v13.jsonl) 来自上述版本的本机桌面同步观察，包含一份快照和 34 批连续更新。会话、轮次、消息和来源客户端的标识已替换，时间与正文均已替换。与判断无关的字段已删除，无关更新路径使用 `ignored`。版本、修订顺序、可见消息类型、完成标记和项目间的关联保留。历史中有已结束的自动审核，此样本不用于证明活动中的审批。

Rust 回归通过真实解析器回放样本，要求只提取一条新进度。模拟 Windows 管道验证两个协议下的自动审核、人工审批、需要回答的问题、断开后等待新快照和恢复采集。桌面测试把脱敏的 13 版更新通过隔离管道送到测试应用，通过模拟 API 检查两种渲染器的气泡、窗口重建和审批抢占。

本机 `pnpm verify`、固定数据回放、工具测试、正式构建隔离检查和 26 项事件通路检查均通过。首次 `pnpm verify:desktop` 的桌面阶段遇到 WebDriver 断开。复用同一构建重跑 `pnpm test:ui --skip-build`，15 项界面用例、22 张截图、2 项冷启动检查全部通过。系统减少动画检查也通过。

## 实机操作

用 `node tools/live-session.mjs prepare --dir .test-artifacts/codex-v13-live` 创建隔离项目，使用同一目录运行 `serve` 并通过 `--binary` 传入新版普通构建。将已启用的碎碎念设置复制到隔离配置时，仍由应用通过 Windows 凭据管理器获取对应的已保存凭据。

日用桌宠仍在运行时，在隔离目录创建包含 `{"identifier":"dev.code-musume.live-protocol13"}` 的 Tauri 配置文件，用 `pnpm tauri build --debug --no-bundle --config <配置文件>` 生成独立实例。构建使用正常 Codex 管道。需要目测气泡时，把两个桌宠拖到不同位置。

在正常启动的 Codex 桌面打开隔离项目，使用本机任务。审阅并信任项目 hooks 后，先让 Codex 输出一条可见进度，再继续工作。确认气泡显示模型小结。分别记录自动审批、人工批准、人工拒绝、需要回答的问题和同步重连。涉及人工审批时由用户操作，结束后关闭隔离桌宠。

使用 `pnpm diagnostics --runtime-file <隔离运行文件>` 读取脱敏诊断。检查 `codexApprovalSync.sessions` 是否已同步，`metrics.lastReceivedVersion` 是否为 13，`visibleMessages` 和 `lastVisibleAtUnixMs` 是否更新。结合 `banterOutcome` 区分尚未发起、请求中、服务失败、成功接收但未能展示和成功展示。诊断不保存正文、昵称、凭据和请求内容。

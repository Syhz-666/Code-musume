# 工作碎碎念验证 — 2026-11-13

在设置的「使用偏好 → 工作碎碎念设置」填入接口协议、包含版本前缀的 HTTPS 基础地址、模型、API Key 和昵称。先用固定样例测试连接，再保存并打开开关。开启后选取的可见回复、工作状态和昵称会发往所选服务。会话内容留在内存，Windows 凭据管理器保存 API Key。

工作中两分钟没有收到新进展时，代码娘会尝试请当前模型写一句陪伴短句。请求可附上同一轮最近一条可见进展。工作信号变弱时，模型只表达在等更新；状态已经无法确认时，暂停请求。陪伴短句与进展总结共用 30 秒间隔和一个请求名额，显示 8 秒。服务不可用或返回无效时使用本地台词；新进展、审批或结束会让晚到的陪伴短句失效。

「空闲碎碎念」可单独开启，默认关闭。桌宠可见并确认空闲时每 30 秒掷骰，6 点尝试生成一句台词，平均约每小时 20 次请求。连续三个 1 开始休息。休息时每 15 秒掷骰，连续两个 6 唤醒。空闲请求只发送角色设定、可选昵称和近期展示过的三句闲聊，台词留在内存。真实工作和审批会接管窗口。隐藏或手动预览期间暂停掷骰。

模型相关测试使用 `127.0.0.1` 上的 HTTP 模拟服务、临时测试密钥和固定骰序。桌面测试将密钥保存在测试进程的内存里，配置写入独立的运行目录。

Windows 上的 Pixi、DOM 空闲碎碎念用例覆盖入睡唤醒、隐藏恢复、窗口重建和工作抢占。

诊断报告的 `banterPipeline` 按中途、陪伴、结束和空闲记录累计请求、结果与气泡计数，并保留最近 128 条链路事件。`source-message` 表示正文已到达调度层，`request` 和 `result` 用请求编号关联，`bubble/published` 和 `bubble/frame-submitted` 区分后端发布与桌宠提交画面。事件使用脱敏后的会话和轮次标签，只保留元数据。`codexApprovalSync.transport` 记录连接与断开阶段及系统错误码，`messageCapture` 统计文字同步基线、中途消息、最终回复和队列丢失。

Codex 的大同步帧在读取时去除可识别的大块 Base64 图片值，并保留轮次和条目的结构。过滤后仍超限的帧按长度跳过，共享连接继续读取后续帧。`codexApprovalSync.transport` 会记录过滤帧数、移除的图片字节数、丢弃帧数及最近一次丢弃原因。

OpenAI 兼容地址示例为 `https://api.openai.com/v1`，Anthropic 兼容地址示例为 `https://api.anthropic.com/v1`。地址以实际服务商文档为准。Anthropic 提示缓存默认关闭，确认服务商支持 `cache_control` 后开启。缓存读写与输入量根据响应的用量字段展示。

## Codex 新版采集顺序

普通启动的 Codex 26.1120.6357.0（内置运行时 0.171.0-alpha.13.2）实测能在一轮结束前写入可见进展，并写入单独标记的最终回复。该版本在验收环境中未开放旧桌面同步管道。

代码娘优先使用已接线 hook 传来的 `transcript_path`。只接收 Codex 会话目录中与主会话 ID 匹配的记录，并要求文件中的轮次边界与 hook 的 `turn_id` 相符。开启、打开或重建读取位置时从文件末尾建立基线，只处理此后新增的完整行。只取 `assistant` 的 `commentary` 和 `final_answer` 输出文字。用户消息、思考、工具内容和历史正文不会进入碎碎念。

已有桌面同步协议 13 和 11 仍可回退。两个版本共用同一个管道，按实际收到的版本解析。两种入口都有数据时，先读文件，再补文件尚未提供的旧同步消息。同轮相同文字只接收一次，最终回复以文件中的有效回复为先。文件缺失、路径或身份无法验证时，旧同步可直接接管。审批继续依赖独立的审批信号。

`fixtures/codex-sync/rollout-0.171.jsonl` 根据 2026-11-25 本机只读观察到的记录形状和顺序重建，替换了正文、会话和轮次身份、时间。固定数据检查覆盖文件增量、半行、超大工具结果、文件重写及不匹配的轮次。桌面检查使用真实 CLI、本地会话文件和模拟模型，验证中途与结束气泡、来源优先级和诊断脱敏。`banterPipeline.codexTranscript` 提供读取计数与最近问题，链路事件标注来源。

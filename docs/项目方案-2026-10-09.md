## 2. 技术选型：Tauri + TypeScript ✅（2026-10-09 已确认）

**推荐理由**：
1. **动画/视觉生态最厚**——这个项目的成败大成在看脸：精灵图、Canvas/PixiJS、SVG/CSS、Live2D-web、Rive、Lottie 全部一等公民；同类最成功案例（BongoCat，23.9k★）就是 Rust/Tauri 系
2. **常驻资源占用小**——桌宠是要挂一整天的，Tauri 内存/体积远小于 Electron
3. **跨平台几乎免费**——将来做 macOS 不用重写
4. **贡献者池与作品集价值**——TypeScript 是最大的开源贡献者群体；同时 Rust 壳层是加分的技术经历

**Rust 的使用面**：v1 只碰壳层胶水（透明窗口/托盘/自启/本地服务），核心逻辑全在 TS——**不等于要成为 Rust 程序员**。

**备选对比（留档，未采用）**：

| 方案 | 何时选它 |
|---|---|
| Electron（纯 JS） | 完全不想碰 Rust；接受内存换省事 |
| .NET / WPF（或 Avalonia） | **你有强 C# 背景**——那就选它（官方天选姬同栈，Windows 原生性能最好；动画生态较薄） |
| Godot / Unity | 不推荐：桌面集成（透明窗/点击穿透/无边框）要额外对抗引擎，收益不成正比 |

> 🧑💻 **选型背景（2026-10-09 补充）**：用户接触过 **C / C++ / C# / Python / TS**。
> → 据此维持 **Tauri + TS**：TS 可直接承担核心逻辑（约 95%）；C/C++ 背景意味着 Rust 壳层（约 5%）无语言障碍；C# 对应备选 WPF/Avalonia（偏好 Windows 原生时）；Python 路线（DyberPet 同系）不做主线。
> ✅ **2026-10-09 已确认：采用 Tauri + TypeScript。**

## 3. 架构：三层 + 两个核心规范

```
Claude Code hooks ──┐
其它 agent（预留）──┤→ [hook CLI] ──本地 HTTP + token──→ [宠物进程]
                    │                                      ├─ ① 事件适配层（每 agent 一个 adapter → 统一事件）
                    │                                      ├─ ② 状态机核心（统一状态 + 迁移）
                    │                                      └─ ③ 表现层（角色包驱动：形态 → 动画）
```

### 3.1 规范 ①：事件协议（agent 无关）

- 目标：**加一个新 agent = 写一个 adapter，核心一行不改**
- 内容：canonical event schema（事件类型、agentId、sessionId、时间戳、可选摘要）；状态归一化规则（把各家 hook 的不同语义映射到统一状态）
- 参照：Claude Code hook 的 payload 字段 + clawd-conduit 的状态映射表

### 3.2 规范 ②：角色包（⭐ 全项目最独特的部分）

**「同一角色多形态」的数据模型**——这是市场上没人做的那格，值得精心设计：

```jsonc
{
  "id": "your-character",
  "forms": [                       // ← 同一角色的多个「形态」：装饰/配色/表情组合
    { "id": "base",   "label": "日常" },
    { "id": "claude", "label": "Claude 形态" }
  ],
  "animations": { "base": { "idle": "...", "working": "..." } },
  "rules": { "agent→form 映射（用户可覆盖）" }
}
```

- **美术经济学**：形态 = 同一角色的**局部变化**（配饰/配色/表情），不是重画一个新角色——这是可持续出图的关键
- **互通**：兼容「Codex 宠物包」格式（精灵图 + manifest）→ 互操作性是开源项目被生态接纳的路径
- **工具链**：脚手架（生成角色包骨架）+ 校验器（发行前自检）——学 clawd-on-desk 的成熟做法
- **v1 动画载体用精灵图**（简单、通用、与生态格式同构）；Live2D 作为后期可选升级

### 3.3 状态机

- 状态集（v1 目标约 8 个）：`idle / thinking / working / waiting-permission / notification / done / error / sleeping`
- 迁移规则 + 优先级（多会话聚合时取最高优先级）——参照业界已有映射，做扎实

### 3.4 进程与接线

- hook 侧：一个**原生小 CLI**（无 Node 依赖）→ 向 `127.0.0.1:<port>` POST + token
- 🚨 **红线**：hook 永远 `exit 0`、`async`、静默失败——绝不干扰 Claude Code（见决策记录 §5）
- 安装器负责写 Claude Code 的 hooks 配置（可一键卸载）

### 3.5 工程细节（从「天选姬实验」继承的教训）

- **DPI 处理**：物理 / 逻辑坐标务必分清（这是旧项目踩过实坑的地方）
- 单实例、开机自启（可选）、无遥测、local-first——写进 README 当卖点
- 低占用优先（常驻进程）
